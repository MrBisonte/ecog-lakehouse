# ADR-0001: Object storage and open formats for all analytical data

| | |
|---|---|
| Status | proposed |
| Date | 2026-09-19 |
| Deciders | Alexandre Monteiro |
| Supersedes | none |
| Superseded by | |

## Context

Neural recordings and device telemetry are large time series that will outlive any engine or vendor decision. Partners and regulators receive data as files. The product side runs on Azure, where Microsoft Fabric and OneLake read open table formats in place.

## Options considered

| Option | Summary | Rejected because |
|---|---|---|
| Proprietary warehouse as the system of record for analytics | One vendor, one engine, one bill | Lock-in on data that has to outlive any vendor decision; every partner and regulator exchange becomes an export |
| Object storage plus Parquet and an open table format, engines read in place | Data stays in a format any engine reads | chosen |

## Decision

Analytical data lives in object storage (Azure Data Lake Storage Gen2 in the target environment, a local directory in this repository) in Parquet under an open table format. Engines read it in place. Engine choice is made per workload on measured cost and latency, not in advance.

## Consequences

Positive: no migration when an engine changes; Fabric and OneLake read the same files; partner exchanges are file handovers with checksums. Negative: transactional guarantees depend on the table format's catalogue, which becomes a component to operate; teams used to a single warehouse lose one-stop tooling.
