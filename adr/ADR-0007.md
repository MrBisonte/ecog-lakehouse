# ADR-0007: Parquet version 2 for Silver

| | |
|---|---|
| Status | accepted |
| Date | 2026-10-04 |
| Deciders | Alexandre Monteiro |
| Supersedes | none |

## Context

`silver/recording` holds one row per sample. Two of its eight columns say where the sample sits in its record: `sample_idx`, the position, and `ts_ms`, the position in milliseconds. Inside a record both rise by a constant step.

The Parquet version 1 writer stores them plain, four bytes a value. A dictionary does not help: a row group of 198,656 rows sorted by `lid, sample_idx` holds almost only distinct values.

| Measured before the change | Value |
|---|---|
| Row groups of `silver/recording` with a dictionary for either column | 0 of 4,408 |
| Share of the layer's compressed bytes held by the two columns | 39.0 percent each |

Source: the encodings section of [docs/bench.md](../docs/bench.md) at commit `18134c0`, written by `faults/a/encodings.sh`.

## Options considered

The Fault A partition, 7,236,800 rows, written four ways:

| Option | File bytes | `ts_ms` bytes | Rejected because |
|---|---|---|---|
| Version 1, snappy, as before | 76,155,922 | 28,949,874 | The cost this record removes |
| Version 2, snappy | 18,281,020 | 12,542 | chosen |
| Version 1, zstd | 52,958,402 | 17,462,325 | Compresses the plain values, does not remove them |
| Version 2, zstd | 18,040,532 | 3,508 | 1.3 percent smaller than snappy for more CPU on every read; two changes at once. Left to be measured on its own |
| Drop `ts_ms`, derive it from `sample_idx` | not measured | | A contract change on `silver/recording` for a column the version 2 writer already shrinks to bytes |

Source: the same section of `docs/bench.md`.

## Decision

Every Silver dataset is written with `PARQUET_VERSION v2`, compression unchanged. The writer then stores `ts_ms` and `sample_idx` as `DELTA_BINARY_PACKED`. Sort order, row group size, columns and types do not change, so no contract changes.

The scope is Silver. Bronze stays as written: it is append-only and its partitions are never rewritten. Gold and the published files stay version 1 for now, so the browser reads what it read before. `faults/a/fix.sql` follows Silver, because the fixed layout of Fault A is Silver's layout.

## Consequences

Positive:

- The two columns stop being most of the layer. (observed: the Build table and the encodings section of [docs/bench.md](../docs/bench.md))
- No reader in this repository is lost: DuckDB 1.5.5 and the DuckDB 2.0 alpha CLI read every variant with the same row count and sum. (observed: the `same` columns of the encodings section of [docs/bench.md](../docs/bench.md))
- DuckDB-WASM 1.32.0 read the four variants in a browser. (observed by hand on 2026-10-03, [doc/REVIEW.md](../doc/REVIEW.md); not scripted)
- A test keeps a plain `ts_ms` or `sample_idx` out of Silver. (observed: [tests/test_silver.py](../tests/test_silver.py), `test_silver_is_parquet_version_2_and_no_sample_position_is_stored_plain`)

Negative:

- A reader that knows only Parquet version 1 data pages cannot read Silver. None is used here; an outside consumer would have to check.
- The layers no longer share one Parquet version until Gold and the published files follow.
- Every Silver file changes, so every Silver `dataset_version` changes. The evidence keeps the runs of both.
- The saving is on disk. On the DuckDB build the benches use, a query over HTTP receives about the same bytes from either version.
