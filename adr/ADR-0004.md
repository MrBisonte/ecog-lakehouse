# ADR-0004: A decodable lineage identifier on every record

| | |

| Date | 2026-09-19 |
| Deciders | Alexandre Monteiro |

## Context

ALCOA+ and Part 11 require that any reported value be attributable to its original record; ISO 14155 requires source data verification. Rows in a lakehouse are written in parallel and reruns must produce identical output. A Gold row derives from thousands of Silver rows.

## Options considered

| Option | Summary | Rejected because |
|---|---|---|
| Lineage held in a separate metadata catalogue only | Standard approach with Purview or an open catalogue | Answers which pipeline but not which file and bytes a number came from; a catalogue outage or drift leaves rows without provenance |
| Random identifiers (UUID v4) plus a lineage table | Simple to generate | Every trace is a join; random keys destroy locality in Parquet and PostgreSQL indexes |
| Hash chain per row | Tamper evident by construction | Not decodable without a lookup; per-row hashing cost; poor compression |
| Accumulated sequence carried from the previous record | Proven in single-writer OLTP systems | Breaks under parallel writers and reruns; needs a table to decode |
| ULID-shaped identifier whose 80 non-timestamp bits encode the hierarchy, with file and dataset digests for integrity | Decode is a bit shift; forward trace is a range scan; sorts and indexes like any ULID | chosen |

## Decision

Every record in Bronze, Silver and Gold carries a 128-bit identifier in the ULID layout: 48 bits of first-ingestion timestamp, then layer, experiment, ingested file, run, channel and segment. Samples reference their record; aggregates carry the record plus a sample range. Integrity is separate: a digest per ingested file and a digest per dataset version. A catalogue can index the same identifiers; it is not the source of truth for them. The bit layout is in `doc/spec.md` section 12.

## Consequences

Positive: any number in any report decodes to its source file and digest without a join; every row derived from one file is a prefix range; identifiers are native UUID columns, index-friendly and prunable. Negative: a derivation that spans several records needs an explicit edge table; the bit budget is a design commitment (16 bits of files per environment, 10 bits of channels) that has to be revisited if exceeded; the encoding must be documented and versioned like a schema.
